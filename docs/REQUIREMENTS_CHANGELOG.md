# MagicGesture 需求变更记录

> 本文档持续记录产品负责人已经明确确认、会影响现有功能行为的需求变更。  
> 这里只记录 G01–G35 现有范围内的稳定性、交互和发布需求，不作为新增手势或二期功能的开发授权。

## 2026-10-03：G01–G35 对外名称统一及 G35 指南图片

- G01–G35 对外名称以 `IDE_DEVELOPMENT_HANDOFF.md` §1.1 和 `GestureArchitecture.kt` 中的 `GESTURE_DISPLAY_NAMES` 为唯一最新清单；首页、校准页、签到解锁提示和映射文档同步使用该表。
- G24 最新名称为“单指枪·横向”，G25 为“单指枪·竖向”，G35 为“双指枪·竖向”；内部枚举、功能开关键和历史持久化键不重命名，避免破坏升级兼容。
- 新增 G35 独立透明图片 `gesture_two_finger_gun.png`：食指与中指水平指向左侧，拇指在食指第二关节 PIP 外侧向上，环指与小指收拢；首页不再复用普通双指并拢图片。
- 本次没有获得修改 G35 识别算法的授权。当前算法仍识别“两指并拢向上、拇指侧伸、保持 1 秒”，与新图片姿势存在差异，必须由产品负责人另行确认后才能调整识别条件、姿势说明和回放测试。

## 2026-10-03：模型异步初始化必须随服务生命周期释放

- 同一前台服务实例同时只能执行一个 MediaPipe 手部模型初始化任务，重复启动命令不得并行创建多个 `HandLandmarker`。
- 模型初始化完成时必须确认服务仍存活且初始化代次有效；服务已经停止或任务已经过期时，不得把模型写回 Service，必须立即关闭未发布的 `HandPipeline`。
- 服务销毁必须使进行中的初始化任务失效，并关闭已经发布的识别管线；过期任务不得再弹出初始化失败提示。
- 构建通过不能代替真机内存验收；发布前需覆盖启动后立即停止、快速连续启停和模型加载中退出，并观察原生内存是否回落。

## 2026-10-03：G35 正式纳入当前产品范围

- 产品负责人确认 G35 已完成开发并正式纳入当前版本，现有产品与测试范围由 G01–G34 调整为 G01–G35。
- G35 为“两指并拢向上”：食指与中指并拢向上、拇指向侧面伸出、无名指与小指收拢，稳定保持 1 秒后执行默认动作“向上滑动”，主要用于切换到下一个短视频。
- G35 归入第 12 次签到解锁的“点赞手势与高级手势”功能包；第 12 次有效签到后应拥有 G01–G35 全部编号。
- G35 当前状态为代码完成、JVM 测试与 Debug 构建已通过，仍需完成短视频翻页、左右手、不同距离以及与两指媒体/V 字/比心互斥的真机验收。
- 当前继续冻结新手势开发：未经产品负责人明确重新立项，不得增加 G36 或后续新编号；二期真实上线门槛保持不变。

## 2026-10-03：G24 更名为手枪手势并与 G12 比心互斥

- G24 对外名称由“左 L 手形”统一改为“手枪手势”，默认动作仍为返回，编号、功能开关和本地映射键不变。
- 食指继续要求水平指向左侧；大拇指必须在食指第二关节（PIP）外侧、靠近掌心/手腕的一侧竖起，不再要求越过食指第三关节（MCP），同时不能贴住 PIP 或 MCP。
- 2026-10-03 真机反馈原规则过严后，位置基准由 MCP 改为 PIP：拇指尖沿食指方向位于 PIP 后方至少约15%掌宽，并且拇指尖距 MCP、PIP 均至少约35%掌宽；原45°–90°夹角和其余三指收拢条件继续保留。
- G12 拇指压住食指 PIP/MCP 或靠近食指尖时不得进入 G24；完整手枪姿势也不得进入 G12。两者增加双向互斥回放测试，参数仍需真机校准。
- 比心释放判定同步覆盖食指尖、PIP 和 MCP 三个接触区域：只有拇指尖同时远离三处才算松开，避免关节接触式比心刚进入候选就因食指尖距离较远而被取消。

## 2026-10-03：收藏位置标定面板支持上下切换

- 收藏按钮可能位于第三方 App 页面最底部，固定底部面板不得遮挡目标或阻止准星落点。
- 标定操作面板增加“面板上移/面板下移”，用户可按目标位置在屏幕顶部和底部之间切换。
- 移动面板只调整悬浮操作区，不改变已经选择的准星坐标，也不把触摸传递给底层 App。
- 面板位于顶部时隐藏原顶部说明卡片，避免重叠；测试点击、人工确认和坐标保存规则保持不变。
- 标定操作面板不再提供“重置”按钮，仅保留取消、移动面板和测试位置。

## 2026-10-03：G24 左 L 手形增加夹角约束

- G24 除原有“食指水平向左、拇指向上、其余三指收拢、保持约 0.6 秒”外，新增食指与拇指方向夹角要求。
- 夹角有效范围为 45°–90°，包含 45° 和 90°边界。
- 夹角使用拇指根部至拇指尖、食指根部至食指尖两条方向向量计算，不使用单纯的指尖距离。
- 小于45°或大于90°不得进入 G24 保持状态；G25 及其他手势规则不变。

## 2026-10-02：多人、多手画面中的控制权规则

### 背景

用户距离摄像头较远或画面中出现其他人时，可能同时检测到多只手。旧实现只让 MediaPipe 返回一只手并直接取第一项，无法保证被识别的是最靠近摄像头、实际想要操作的手，可能导致后方人员误触动作。

### 已确认规则

1. 不增加授权动作，不要求用户先用食指或其他姿势取得控制权。
2. 画面中存在多只手时不因多手本身停止识别。
3. 视觉上最靠近摄像头的手独占控制权；即使该手没有做有效手势，后方其他手的任何手势也不得触发动作。
4. 使用掌部骨架的相对尺寸估算前后关系，不使用容易随姿势变化的指尖外接范围：主要参考手腕 0 和掌指关节 5、9、13、17。
5. 当前控制手持续锁定；另一只手的掌部尺度至少领先约 20%，并持续约 250ms，才允许接管，避免两手大小接近时逐帧跳变。
6. 当前控制手短暂遮挡时保留控制权；连续丢失约 300ms 后，才由当前画面中视觉上最近的手接管。
7. 控制权切换时必须清空上一只手的全部识别状态，包括静态保持进度、G22/G23 倒计时、轨迹、双击、组合动作、持续音量状态和光标平滑状态；新控制手从零开始识别。
8. 第一阶段最多检测两只手。发布前根据目标机型的识别帧率、耗电和发热结果，再决定是否扩大到三只手。
9. 单目摄像头没有真实深度，只能根据视觉尺度估算相对前后。该限制必须通过真机测试验证，不得宣传为精确距离或精确 80cm 判断。

### 初始实现参数

| 参数 | 初始值 |
|---|---:|
| MediaPipe 最大检测手数 | 2 |
| 初次控制手稳定时间 | 200ms |
| 挑战手掌部尺度领先比例 | 20% |
| 挑战手连续领先时间 | 250ms |
| 当前控制手连续丢失后接管 | 300ms |

### 验收要求

- 前方手保持自然状态时，后方手完成 G22、G23 或其他手势不得触发动作。
- 前方手正常完成手势时，后方手的姿势不得干扰识别结果。
- 后方手明显伸到前方并持续达到接管条件后，可以取得控制权。
- 两只手短暂交叉、遮挡或尺寸轻微波动时，不得频繁切换控制权。
- 接管发生时，上一只手已经积累的保持或轨迹进度不得由新手继续完成。
- 覆盖 40cm、60cm、80cm、100cm，两人同框、左右交叉、前后交换、不同大小手掌、左右手组合。
- 记录启用双手检测前后的识别帧率、CPU、耗电和发热；构建通过不能替代真机验收。
