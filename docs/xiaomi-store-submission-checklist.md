## 5. 权限与敏感能力（小米最关键）

小米对敏感权限走**单独申请**流程，不是仅填写说明：官方文档入口
- 应用权限申请操作指南：`https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2117`
- 权限使用及申请标准：`https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2156`

需申报的能力与口径：

| 权限/能力 | 处理 |
|---|---|
| 相机 | 逐权限填用途，复用 `docs/huawei-permission-statement.md` §3 |
| 悬浮窗（SYSTEM_ALERT_WINDOW） | 敏感权限，单独申请，复用 §2 并附演示视频 |
| 无障碍（BIND_ACCESSIBILITY_SERVICE） | 敏感权限，单独申请，复用 §1（必要性论证 + 不读取窗口内容 + 可随时关闭），附视频 |
| 前台服务 / 后台相机 | 小米对**自启动与后台行为**审查最严，需说明：仅用户主动启动后才常驻前台服务、常驻通知可见、可一键停止、无自启动 |
| 通知 | 复用 §3 |

核心论证口径（与华为一致）：不使用无障碍服务则全部手势控制功能无法实现，属核心功能而非附加功能；`canRetrieveWindowContent=false`；不读取页面文字/密码/聊天内容；不自主决策、不按内容自动点击。

## 6. 小米渠道特有风险

1. **自启动/后台保活审查**：不得声明或尝试自启动、相互唤醒；我们的前台服务只在用户点击启动后出现，符合，但需在说明中明确写出。
2. **后台相机使用**：MIUI 对后台相机敏感，需在权限说明中强调「仅用户主动启动后使用、通知可见、可随时停止」。
3. **隐私弹窗**：小米要求首次启动有隐私政策弹窗并征得同意（我们已有首启同意门，是加分项）。
4. **权限申请时机**：不得冷启动一次性申请全部权限；我们按功能触发申请，符合。
5. **图标规范**：小米有自家图标圆角/无透明规范，上传后若提示不合规，按后台示例重做。

## 7. 提交顺序

1. 完成 §2 三项（账号实名、备案号、软著按需）。
2. 创建应用并占用包名 `com.magicgesture.app`。
3. 上传 APK，跑小米的自动检测（权限/隐私合规/稳定性），按结果整改。
4. 填 §4 文案、素材、分级、个人信息。
5. 按 §5 提交敏感权限申请（无障碍、悬浮窗），附演示视频。
6. 提交审核，等待结果（通常 1–3 个工作日）。

## 8. 驳回应对

| 驳回表现 | 应对 |
|---|---|
| 敏感权限用途不明 | 提交 `docs/huawei-permission-statement.md` §1/§2 全文 + 演示视频 |
| 后台行为/自启动违规 | 说明无自启动、无相互唤醒，前台服务仅在用户启动后常驻且可停止 |
| 隐私政策不可访问或内容不全 | 检查 HTTPS 页面、含主体/联系方式/SDK 清单/删除方式 |
| 图标/截图不合规 | 按后台规范重导出（图标去透明通道、截图尺寸） |
| 描述与实际不符 | 描述以审核指南 §7.5 为准，不写绝对化表述 |
