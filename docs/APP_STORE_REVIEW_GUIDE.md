## 2. 最终权限申报

| 权限/能力 | 审核用途建议 |
|---|---|
| `CAMERA` | 用户主动启动后，使用前置摄像头在设备本机识别隔空手势；用户主动触发 V 手势自拍时保存照片 |
| `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_CAMERA` | 用户离开应用页面后维持已主动启动的摄像头手势识别，并通过常驻通知提示服务正在运行及提供停止入口 |
| `POST_NOTIFICATIONS` | Android 13 及以上展示前台服务运行状态和停止入口 |
| `SYSTEM_ALERT_WINDOW` | 在其他 App 上方显示手势光标、状态点、识别反馈、倒计时和收藏位置标定面板 |
| AccessibilityService | 把用户主动手势转换为点击、滑动、返回、桌面、最近任务、截图及媒体操作；不读取窗口内容，`canRetrieveWindowContent=false` |
| `<queries>` 应用可见性 | 仅查询可启动应用和默认音乐应用，用于用户配置“打开应用”动作及媒体播放回退，不枚举无关应用 |

不同市场可能不接受普通应用使用 `SYSTEM_ALERT_WINDOW`，或要求单独说明/申诉。必须在目标市场提交前逐家确认，不能把一个市场的批准视为其他市场批准。

## 3. Google Play Data Safety 填写草案

Google Play 把“收集”定义为把数据传输到设备外。基于当前无网络权限、无服务端和本机处理实现，建议初始答案为：

- 应用是否收集或共享规定的用户数据：**否**。
- 数据是否在传输中加密：当前没有向设备外传输数据，此问题按后台实际表单处理，不虚构“已加密传输”。
- 是否提供数据删除请求：应用没有开发者持有的远程用户数据；本机设置可通过清除数据/卸载删除，相册图片由用户自行删除。
- 是否完成独立安全审查：**否**，除非发布主体实际完成并持有证明。

注意：本机处理的摄像头画面、前台 App 包名和用户保存图片仍须在隐私政策与显著披露中说明。最终答案还必须复核所有第三方 SDK；若未来加入联网、崩溃统计、广告或账号，本草案立即失效。

## 4. Accessibility API 申报草案

- `isAccessibilityTool`：建议选择**否**。本应用不是为残障人士专门设计的辅助工具，而是一般用途的隔空控制产品。
- 使用原因：无障碍服务是核心跨应用控制链路，用来执行用户主动手势明确绑定的点击、滑动、全局导航、截图和媒体动作。
- 数据访问：订阅窗口变化事件以取得前台应用包名；不读取窗口内容、页面文字、密码、聊天内容或控件树。
- 自动化边界：不自主决策，不按页面文字自动点击；只有用户主动做出已配置手势时才执行确定性动作。
- 用户控制：开启前展示独立披露，提供“我已了解并继续”和“暂不开启”；用户可随时在系统设置关闭服务或在应用内停止控制。

应用商店描述中也应明确写出无障碍用途，不能只写在隐私政策里。

## 5. 显著披露文案与流程

当前应用在跳转无障碍设置前展示独立弹窗，包含能力用途、本机摄像头处理、不读取页面文字、可随时关闭，并提供继续与拒绝按钮。审核前应录屏验证完整流程。

建议商店审核视频连续展示：

1. 冷启动并进入首页。
2. 点击开启无障碍服务，完整展示披露内容。
3. 点击“暂不开启”，证明拒绝不会被视为同意。
4. 再次进入披露，点击“我已了解并继续”，进入系统无障碍页面。
5. 开启服务，回到应用并主动启动控制。
6. 展示前台服务通知、摄像头系统指示和悬浮状态点。
7. 在另一 App 中用手势完成一次点击或滑动。
8. 返回应用点击停止，证明摄像头与悬浮控件结束。

视频不得剪掉披露、拒绝路径、系统授权页面或功能实际使用过程。旁白/字幕应与最终版本行为一致。

## 6. 商店文案必须披露的限制

- 隔空识别受光线、背景、手部距离、设备性能和厂商后台策略影响，不宣传“百分百准确”。
- 最近手控制是单目前置摄像头根据视觉尺度估算，不宣传为精确距离测量。
- 自拍、截图和长截图只有用户主动触发才保存；说明相册保存位置。
- 离线签到与设置只保存在本机，清除数据、卸载或换机可能丢失。
- 当前没有云同步、账号、支付、广告或联网权益。
