# MagicGesture UI 设计稿落地强制规范

> 本规范适用于根据总设计图、截图或 Mockup 实施当前及未来获准开发的全部 Android 页面。

## 1. 基本原则

- 不改变既有业务规则、状态机、隐私边界和 G01–G35 范围，尽可能准确还原已确认设计稿。
- 建立可复用的颜色、间距、圆角、字体、卡片、按钮、标签和状态组件。
- 保证不同屏幕尺寸、显示缩放和字体缩放下仍可阅读、滚动和点击。
- 分开管理视觉参考、业务事实、素材和交互状态，禁止把错误文案或过期功能固化进图片。

冲突优先级：产品负责人当前明确指示；`AGENTS.md` 与权威需求文档；已确认代码行为；已确认设计稿；实现者视觉推断。设计稿是视觉来源，不是新增功能、付费体系、手势编号、权限、联网能力或业务状态的授权。发现冲突必须先列出问题和建议方案，等待确认，不得静默猜测。

## 2. 实施前置条件

1. 阅读仓库规定的必读文档和本规范。
2. 确认工作目录、分支、HEAD、远程关系及全部未提交改动。
3. 列出页面入口、状态、操作、跳转和返回行为。
4. 列出未授权、启动中、运行中、停止、锁定、签到等全部设计状态。
5. 建立素材清单，逐项标记为：仓库已有、Android 样式或矢量实现、可无损提取、需要产品负责人提供。
6. 编码前提交页面结构、素材需求、设计冲突和实施顺序，确认后才开始修改代码。

## 3. 素材处理强制规则

### 3.1 禁止事项

- 禁止从含文字、按钮、卡片、状态栏或其他界面元素的区域强行截图。
- 禁止使用带残影、接缝、黑边、白边、矩形底色、噪点或不完整透明边缘的切片。
- 禁止把整张页面设计稿作为页面背景，用假界面覆盖真实控件。
- 禁止下载来源、版权或授权不明的网络素材。
- 禁止用 emoji 代替正式手势示意图、导航图标或功能图标。
- 禁止在图片中固化会变化的动作、签到进度、权限状态、按钮文案或映射结果。
- 禁止擅自生成或重绘会影响手势姿势含义的图片。

### 3.2 应由界面组件实现

纯色与渐变背景、圆角卡片、描边、分割线、阴影、可控发光、按钮状态、开关、滑杆、进度环、状态圆环、签到进度、简单线性图标和动态文字，原则上使用 Android 原生样式、Shape、VectorDrawable 或可复用组件实现。交互元素必须是真实控件，具有明确点击区域、状态和无障碍语义。

### 3.3 允许提取位图的条件

只有素材边界完整、没有重叠、可获得干净透明或独立背景、不含动态文字与控件、放大后无残影毛边和拼接痕迹、分辨率满足目标设备时，才能从设计稿提取。提取后必须检查透明边缘、四角、发光范围和缩放效果，未通过不得使用。

### 3.4 必须请求产品负责人提供素材

背景被其他元素遮挡、复杂光带或品牌图形无法干净分离、原图分辨率不足、手势姿势可能误导练习、缺少正式品牌源文件，或需要重新生成图片但尚未获得同意时，必须暂停对应素材制作或页面最终化并交互确认。

请求时必须说明用途、建议尺寸、格式、透明要求、安全区、多倍率需求及页面能否继续搭结构。未经确认不得以低质量切片作为最终素材；临时占位也须事先确认并明确移除条件。

## 4. MagicGesture 专项边界

- 不得新增 G36 或新手势概念。
- G01 固定不可换绑；G28 识别锁不可关闭、不可换绑，不展示虚假的普通映射或开关。
- 首页紫色动作标签读取实时映射；灰色说明只描述姿势和节奏。
- 名称、保持时长、默认动作和解锁归属以权威文档和代码为准。
- Release 不展示会员、订阅、付费解锁、历史用户全开、管理员全开、秘密口令或 `PRO`。
- 签到必须表达“一天一次、断签不清零、永久保留、7 次完成”。
- 权限页面必须反映 Android 真实授权状态。
- 隐私、无障碍、悬浮窗、相机、通知和相册说明必须与实际行为一致。
- Debug 全开能力必须保持构建类型隔离。

## 5. 页面结构与适配

- 设计稿尺寸只作为比例参考，禁止将单一屏幕坐标硬编码到所有设备。
- 区分固定区和滚动区，内容不得被底部导航或系统栏遮挡。
- 适配刘海、挖孔、状态栏、手势导航区和既定横竖屏策略。
- 为中文长度、字体缩放和动态状态预留空间。
- 点击区域必须充足；发光装饰不得拦截点击或覆盖文字。
- 同一视觉语义使用同一组件和参数，动画不得降低识别服务性能或造成持续高负载。

## 6. 实施与验收顺序

1. 确认业务状态和信息架构。
2. 确认素材清单并解决阻塞素材。
3. 建立颜色、字体、间距、圆角和组件规范。
4. 先实现一个代表性页面或状态作为视觉基准。
5. 产品负责人确认后再扩展其他页面。
6. 接入真实数据、权限、映射和签到状态。
7. 完成屏幕、字体缩放和系统栏适配。
8. 进行截图对比、交互回归、构建验证和真机验收。

未确认基准页面前，不一次性批量改造全部页面。每页必须检查层级、间距、圆角、颜色、字体、图标、残影、边缘、拉伸、遮挡、z-order、屏幕适配、系统栏、真实状态和真实数据。视觉验收、功能测试、构建成功、APK 安装及真机验收必须分别记录。

## 7. UI 交接附加要求

- 使用的设计稿和对应状态；
- 新增、复用、提取和待提供的素材；
- 素材来源及透明边缘、分辨率和缩放检查；
- 新建或复用的视觉组件；
- 设计稿冲突与处理结论；
- 已检查的屏幕尺寸、字体缩放和真机效果；
- 未完成的素材、状态和验收；
- 临时占位素材及移除条件。

## 8. 文档维护

- 本文档是无日期长期主规范，不创建按轮次或日期重复的 UI 规范。
- 新页面、状态或素材类型继续遵守本文档；规则变化直接更新本文档并在交接中说明。
- 视觉变化不能替代手势映射、架构、签到需求和行为变更文档的同步维护。
