## 2.2 主体资格：必须企业/组织开发者（2026-10-12 确认）

- **A（推荐）注册个体工商户 → 企业开发者账号**：个体户办理快、成本低，可作为开发者实名主体；随后变更备案主体、软著改企业署名，荣耀重新提交。

- **C 先确认例外通道**：向荣耀客服/运营提交工单，明确两件事——① 个人开发者是否绝对不可上架（有无游戏/工具类例外）；② 个人账号下已创建的应用如何释放包名。成本最低，建议与 A 并行先做。

## 2.3 混合主体方案：华为保留个人、其它渠道用企业（2026-10-12 评估）

**结论：商店层面不冲突，备案层面存在一定风险，可用"先试后定"验证。**

### 可行的依据

| 维度 | 结论 |
|---|---|
| 商店体系 | 各商店互相独立，同一包名可在华为个人账号与荣耀/小米企业账号各自上架，**不存在跨商店包名冲突** |
| 商店内部核验 | 只要做到「该商店的开发者账号主体 = 该商店填写的备案主体」，即可通过。华为配个人备案号、荣耀配企业备案号，各自内部一致 |
| APP 包名 | 官方规则明确「**不同主体的 App，App 包名可相同**」，企业主体可用同一包名 `com.magicgesture.app` 备案 |
| APP 名称 | 官方规则「同主体下名称唯一，**不同主体可以相同**」，企业主体仍可备案「魔法手势」 |

### 风险点（必须逐项处理）

1. **同一款 APP 在两个主体下各备案一份，可能被判重复备案/主体冲突。**
   官方 FAQ 允许包名相同，但实务文章普遍反映「个人 + 企业备案混用」是典型的主体冲突场景，结局可能是管局要求注销其一。
   → **提交企业备案前，先向腾讯云备案客服确认**："同一包名、同一 APP 名称，已在个人主体备案，现以企业主体再备案，是否会被判重复备案、是否需要先注销个人备案？"
2. **APP 域名不可共用**：不同主体的 APP 域名不可相同，且域名实名须与备案主体一致 → 企业备案必须用一个**企业实名的新域名**。
3. **隐私政策主体表述**：同一份 APK 里隐私政策写死的主体，必须与上架账号主体一致。
   → 建议把隐私政策中的开发者主体改为**中性表述**（如「魔法手势开发者」+ 联系邮箱），兼容个人与企业两个主体；避免写死姓名或公司名。改动涉及 `docs/PRIVACY_POLICY.md`、`docs/privacy-policy.html` 与随包 `res/raw/privacy_policy.txt`，改后需重新打包发版。
4. **软著主体**：荣耀企业账号侧最好有企业署名的软著，或个人软著 + **著作权人授权书**（视渠道接受度）。同一软件不能在两个主体各登一份原始著作权，只能二选一 + 授权/转让。
5. **荣耀侧包名占用**：企业账号创建应用前，先在个人账号下删除/注销占用 `com.magicgesture.app` 的应用（App ID `104594875`、`104594996`）。

### 建议走法（先试后定，避免预先二选一）

1. 办个体工商户执照 + 企业实名域名
2. **不注销个人备案**，直接以企业主体提交 APP 备案
3. 若管局放行 → 混合方案成立：华为完全不动（仍个人账号 + 个人备案号），荣耀用企业账号 + 企业备案号
4. 若管局要求清理 → 注销个人备案，并同步把华为后台备案号更新为企业备案号（华为支持「应用转移」把应用迁到已备案主体的账号）
5. 无论哪种结果，软著与隐私政策都需要先做兼容处理

## 5. 权限与敏感能力

需如实申报（荣耀 MagicOS 对无障碍/悬浮窗的审查口径与华为接近，但以后台实际要求为准）：

| 能力 | 说明口径 |
|---|---|
| 相机 | 复用 `docs/huawei-permission-statement.md` §3：仅用户主动启动后使用前置摄像头本机识别，自拍时保存 |
| 悬浮窗 | 复用 §2：光标、状态点、反馈、倒计时、标定面板 |
| 无障碍 | 复用 §1：手势转换为系统操作，核心功能，`canRetrieveWindowContent=false`，不读取窗口内容与页面文字，可随时关闭 |
| 前台服务 | 复用 §3：常驻通知可见、可一键停止 |

华为侧的通过经验可复用：无障碍被归入「专项敏感权限声明」表单时，勾选语义最接近的一项（华为选的是「用于用户创建自动化任务」），并在审核备注里澄清**不涉及短信与通话场景**、附演示视频。若荣耀后台有同类强制必选项，按同样处理并记录到本文。

**优势**：荣耀是真机（ALP-AN00）所在渠道，授权引导与「保持授权不丢失」方案做过真机实测，授权引导文案无需返工。
