## 3. 近期主线工作

### 3.1 性能优化（2026-10-13 起，代码完成，部分真机已量测）

- 启动流程改为「相机会话 + MediaPipe 模型 + 首帧推理结果」全部就绪后才置为运行中，最长 20 秒失败关闭服务。
- `hand_landmarker.task` 改为 APK 内不压缩；相机优先选择覆盖 20fps 预算的最低 AE FPS 区间。
- 加入「单帧在途」背压后，进程冷启动 READY 由 21.53s 降到约 2.6s（三次量测 2.863s / 2.739s / 2.306s）。

### 3.2 低端机帧率瓶颈定位与修复（2026-10-19，Redmi Note 11R 真机已量测）

| 项 | 优化前 | 优化后 |
|---|---|---|
| Kotlin YUV→ARGB 转换 | 125 ms/帧 | 约 30 ms/帧 |
| 有效帧率 | 3.8 fps | 12.4 fps |
| 5 秒窗口帧数 | 约 60 帧被丢弃 | 50–66 帧 |

- 三项修复：① 三平面批量拷贝 + 定点整数色彩换算 + 像素数组复用；② 在途上限 1 帧 → 2 帧，使 CPU 转换与 GPU 推理重叠；③ 超过 3000ms 无回调时重开闸门（原实现一旦回调丢失即永久拒绝所有帧，表现为「彻底识别不了」）。
- 真机 90 秒使用：手势事件 69–117 次 / 10 秒（原约 35 次），真实触发 G01/G02/G06/G12/G22/G23/G24/G25/G31/G35，无 `inference failed`、无崩溃、无闸门告警。
- 5 分钟耐久：多数窗口 10–13 fps；中段出现一次劣化（转换升到 70–171ms、降到 2–5 fps）后自行恢复，当时 CPU 55.4°C、Thermal Status 0，**判断非热节流**，怀疑后台负载/内存回收抖动（该机 4GB、空闲约 60MB、swap 已用 1.5GB），尚未定位具体来源。
