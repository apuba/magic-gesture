# 第三方 App 收藏按钮位置标定需求文档

> 状态：首版代码链路已实现，等待真机验收
> 版本：V1.0 草案  
> 日期：2026-10-02

## 1. 背景与目标

“收藏”指对当前第三方 App 中正在浏览的内容执行收藏按钮点击，例如快手视频、抖音视频或小红书笔记的收藏功能，不是收藏或启动某个 App。

不同第三方 App 的收藏按钮位置、页面结构和无障碍信息不同，且可能随版本更新变化。首版采用用户自行标定屏幕位置的通用方案：按前台 App 和屏幕方向保存收藏按钮坐标；以后再次触发收藏手势时，自动调用对应配置完成点击。

目标：

- 一个“收藏当前内容”动作支持多个第三方 App。
- 用户只需对每个 App、每种屏幕方向首次标定一次。
- 不依赖读取第三方 App 页面文字或控件树。
- 未定义、配置不匹配或无法安全执行时不盲点。
- 收藏执行期间独占手势识别，避免同时触发滑动、点赞或媒体动作。

## 2. 名词定义

| 名称 | 含义 |
|---|---|
| 收藏动作 | 手势映射中的统一动作“点击当前应用收藏按钮” |
| 当前应用 | 收藏手势触发时位于前台的第三方 App，以包名唯一识别 |
| 位置配置 | 某个 App 在指定屏幕方向下的收藏按钮相对坐标及标定元数据 |
| 标定层 | 覆盖在当前第三方 App 上方、用于选择收藏按钮位置的透明悬浮界面 |
| 执行独占态 | 收藏标定或点击期间暂停其他全部手势检测与动作执行的状态 |

## 3. 用户故事

1. 用户第一次在快手中触发收藏手势时，系统提示快手尚未定义收藏按钮位置，并允许立即标定。
2. 用户不离开当前快手页面，通过覆盖层将准星放到收藏按钮中央，测试并保存。
3. 用户以后在快手触发同一动作时，系统直接点击快手已经保存的位置。
4. 用户在小红书首次触发时，系统单独要求定义小红书的位置，不覆盖快手配置。
5. 用户旋转手机后，如果当前方向尚未定义，系统要求为该方向重新标定，不复用另一方向坐标。
6. 用户可以在魔法手势设置页查看、重新定义或删除已经保存的 App 配置。

## 4. 首次触发流程

```text
识别到收藏手势
  → 进入收藏动作独占态
  → 读取当前前台 App 包名、名称、屏幕方向和可操作区域
  → 查找对应位置配置
      ├─ 已配置且有效：执行收藏点击
      └─ 未配置/不匹配：显示首次定义提示
            ├─ 现在定义：进入原页面悬浮标定层
            └─ 暂不定义：退出独占态，不点击、不进入动作冷却
```

首次提示文案：

> 当前应用“{App 名称}”尚未定义收藏按钮位置。请先标记当前页面的收藏按钮。

操作按钮：`现在定义`、`暂不定义`。

要求：

- 提示在当前第三方 App 上方显示，不跳回魔法手势主页。
- 记录进入提示前的第三方 App 包名，后续保存前必须再次校验。
- 魔法手势自身、系统桌面、系统设置及无法确定包名的窗口不允许建立收藏配置。

## 5. 位置标定方案

### 5.1 标定界面

点击“现在定义”后，在当前页面显示可触摸的透明标定层：

- 页面轻微变暗，但底层收藏按钮仍清晰可见。
- 顶部显示当前 App 名称和操作说明。
- 中间显示可拖动十字准星。
- 用户点击任意位置时，准星中心移动到该位置。
- 支持拖动准星进行精调。
- 准星附近提供局部放大镜，避免手指遮挡目标。
- 底部操作：`取消`、`重置`、`测试位置`。

说明文案：

> 将十字准星中心移动到收藏按钮中央。标定过程中不会点击页面。

标定层必须拦截触摸，用户移动准星时不能把触摸传递给第三方 App。

### 5.2 测试与确认

点击“测试位置”前显示明确提示：

> 测试会真实点击一次收藏按钮，可能会收藏或取消收藏当前内容。

确认测试后：

1. 临时隐藏标定层。
2. 通过无障碍 `dispatchGesture` 点击准星位置。
3. 点击完成后恢复确认层。
4. 询问“是否成功点击收藏按钮？”

确认操作：

- `点击成功，保存`：保存配置并退出独占态。
- `位置不准，重新调整`：回到标定层。
- `取消`：不保存并退出独占态。

若点击注入失败，直接提示“测试点击失败，请重新调整或稍后重试”，不得提供“保存成功”的假反馈。

## 6. 坐标保存规则

禁止只保存绝对像素坐标。位置应相对于当前可操作显示区域归一化：

```text
normalizedX = (clickX - usableLeft) / usableWidth
normalizedY = (clickY - usableTop) / usableHeight
```

执行时根据当前可操作区域反算实际坐标：

```text
clickX = usableLeft + normalizedX * usableWidth
clickY = usableTop + normalizedY * usableHeight
```

每条配置至少保存：

| 字段 | 说明 |
|---|---|
| packageName | 第三方 App 包名，主键组成部分 |
| appLabel | 保存时的应用显示名称，仅用于 UI |
| orientation | `PORTRAIT` 或 `LANDSCAPE`，主键组成部分 |
| normalizedX / normalizedY | 收藏按钮归一化坐标 |
| screenWidth / screenHeight | 标定时屏幕尺寸，用于诊断 |
| usableArea | 标定时状态栏、导航栏扣除后的区域信息 |
| appVersion | 标定时第三方 App 版本，便于更新后提示复查 |
| updatedAt | 最后标定时间 |

首版每个包名允许保存一条竖屏配置和一条横屏配置。竖屏与横屏不得互相回退使用。

## 7. 后续收藏执行

已存在有效配置时：

1. 收藏手势成功识别后进入执行独占态。
2. 再次确认前台包名和屏幕方向与配置一致。
3. 将相对坐标换算为当前实际坐标。
4. 检查坐标位于可操作区域内。
5. 通过无障碍服务发送一次短点击。
6. 点击注入成功后提示“已点击 {App 名称} 收藏位置”，进入全局动作冷却。
7. 注入失败则提示失败，退出独占态，不进入成功冷却。

反馈只能表述“已点击收藏位置”，不能直接表述“收藏成功”。坐标点击无法确认第三方 App 的业务结果；若内容原本已经收藏，再次点击可能会取消收藏。

## 8. 多 App 与配置管理

收藏位置按 `packageName + orientation` 独立存储，不设置“应用一、应用二”等固定槽位，也不限制为四个 App。

“手势练习与校准”新增“收藏按钮位置”管理区，展示：

| 应用 | 竖屏 | 横屏 | 操作 |
|---|---|---|---|
| 快手 | 已定义 | 未定义 | 查看 / 删除 |
| 小红书 | 已定义 | 已定义 | 查看 / 删除 |

管理能力：

- 查看 App 名称、方向和最后定义时间。
- 删除某一方向配置或该 App 全部配置。
- 提示用户回到目标 App 后触发收藏手势进行重新定义。
- 不允许在魔法手势主页凭空选择坐标，因为主页看不到第三方 App 的真实按钮。

## 9. 独占状态与冷却规则

下列阶段均暂停其他全部手势检测，不输出光标、进度、候选状态或其他动作：

- 首次未定义提示显示期间。
- 标定层显示期间。
- 测试点击及测试确认期间。
- 正式收藏点击提交期间。

退出规则：

- 暂不定义、取消标定、删除/放弃：立即退出独占态，不进入动作冷却。
- 点击注入失败：退出独占态，不进入成功冷却。
- 正式点击注入成功：退出独占态，并进入当前统一全局冷却。
- 标定提示或标定层超过 30 秒无操作：自动取消并退出独占态。

## 10. 异常与安全边界

- 当前前台 App 与开始标定时不同：禁止保存并提示重新开始。
- 屏幕方向发生变化：取消当前标定，要求在新方向重新定义。
- 坐标位于状态栏、导航栏、系统手势区或屏幕外：禁止保存。
- 第三方 App 更新版本后不自动删除配置，但首次执行可提示“应用已更新，如位置变化请重新定义”。
- 多窗口、悬浮小窗、分屏模式首版不支持；检测到时不执行坐标点击。
- 锁屏、权限弹窗、系统设置、桌面、魔法手势自身均不执行收藏坐标点击。
- 用户关闭无障碍、悬浮窗权限或手势功能时，不进入标定流程。
- 不读取第三方 App 页面内容，不上传包名、坐标或使用记录。

## 11. 首版范围与延期项

### 首版必须实现

- 新动作“点击当前应用收藏按钮”。
- 自动识别前台 App 和屏幕方向。
- 未定义提示、原页面标定层、准星拖动和测试点击。
- 每个 App 各一套竖屏/横屏配置。
- 多 App 配置存储、查看和删除。
- 执行独占态、成功冷却和准确的成功/失败反馈。

### 暂不实现

- 根据控件文字或控件 ID 自动查找收藏按钮。
- 判断内容是否已经收藏。
- 保证点击后第三方 App 业务收藏成功。
- 同一 App 同一方向保存多个页面模板。
- 分屏、自由窗、悬浮小窗适配。
- 云端同步收藏位置配置。

## 12. 验收标准

1. 快手未配置时触发收藏手势，只出现定义提示，不发生页面点击。
2. 在快手竖屏完成标定并保存后，再次触发可点击已定义位置。
3. 小红书可建立独立配置，不覆盖快手。
4. 只有竖屏配置时横屏触发必须要求重新定义，不能沿用竖屏坐标。
5. 标定期间移动准星不会操作底层页面。
6. 测试点击失败时不能保存为“已验证”状态。
7. 前台 App 在标定过程中发生变化时不能保存。
8. 点击执行期间不会同时触发光标、滑动、点赞、媒体或其他手势。
9. 取消或失败不进入成功冷却；正式点击注入成功后才进入冷却。
10. 配置页面能够分别删除某个方向和某个 App 的全部收藏位置。

## 13. 已采用的首版产品决定

1. `FAVORITE_CURRENT` 默认绑定 G21 OK 手势，同时保留在动作选择器中供其他手势换绑。
2. 首版必须经过真实测试点击并由用户确认成功后才能保存位置。
3. 首版接受收藏按钮为切换按钮的客观行为，并在测试前明确提示再次点击可能取消已有收藏。
4. 第三方 App 配置不设四槽位或业务数量上限，仅按本地存储能力做合理保护。
